# S1 — Claude Code Stop hook surface

Status: **documentation evidence plus partial live observation; full live run pending HQ-5** (the `claude` CLI login on the build machine expired, so a nested headless session cannot reach the model). Installed version: Claude Code 2.1.278. Docs read 2026-10-17: code.claude.com/docs/en/hooks, /hooks-guide, /headless, /mcp, /plugins/*.

Rerun: `node docs/spikes/s1-stop-hook/run.mjs` (headless, both render modes) and the interactive check in `s1-stop-hook/README.md`.

## Answer

Use `last_assistant_message` for the turn text and the transcript only for tool-use names, best-effort. Continue the model with `{"decision":"block","reason":feedback_text}` on stdout, exit 0. Send the user notice in the top-level `systemMessage` field of the same JSON: the docs call it a universal "warning message shown to the user", and Stop is not on the list of events that discard it. `notice_via_model` stays as a fallback behind one adapter switch (`render_channel: system_message | via_model`). The default is `system_message` until the live run says otherwise. Exit 2 with stderr does the same continuation and is the shim's fallback if JSON output is ever ignored, for example when profile output corrupts stdout.

## Observed live (2.1.278, this machine)

The aborted runs still executed the SessionStart and UserPromptSubmit hooks:

- SessionStart stdin: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `source: "startup"`.
- UserPromptSubmit stdin: those fields, plus `prompt_id` (UUID), `permission_mode` and `prompt`.
- `--output-format stream-json --verbose` emits `system:hook_started` and `system:hook_response` events with each hook's stdout.
- Hook stdout reaches the session as context; the `hook_response.output` field carried the inject text.
- An auth failure ends the session without firing Stop, which matches "API errors fire StopFailure instead".

## From the docs (not yet observed on Stop)

| Question | Documented answer | Design consequence |
| --- | --- | --- |
| Final text at Stop | `last_assistant_message` holds "the text content of Claude's final response"; transcript "may not yet include" the latest messages | Adopt plan §2.1 correction in 05 |
| Markdown verbatim? All text blocks or last? | Not documented | Live run checks code fences and curly apostrophes; the segmenter tolerates either |
| Turn id | `prompt_id` common field, "UUID identifying the user prompt currently being processed" | Shim uses `prompt_id` as `turn_id` when present, else sha256(session_id + user message) as 05 says. Stability across continuations is unverified, and the adapter's own per-turn pass count stays the source of truth |
| `stop_hook_active` | true when "already continuing as a result of a stop hook" | Passed as `continuation`, cross-check only (05) |
| `reason` visibility | "Tells Claude why it should continue"; user visibility on Stop not documented | Do not rely on `reason` for the user notice |
| `systemMessage` on Stop | Universal field, "shown to the user"; Stop not listed among discarding events | Default render channel |
| `hookSpecificOutput.additionalContext` on Stop | Forces a continuation like block | Not usable as a passive channel; unused |
| Exit 2 | stderr becomes the continuation reason | Fallback path |
| Block cap | 8 consecutive continuations, reset on any tool call | Pass cap 2 fits |
| Timeouts | Command hooks default 600 s; UserPromptSubmit 30 s; on timeout the hook "renders no decision" (fails open) | Register Stop with `timeout: 10`; adapter's 6 s cap binds |
| Windows shell | Git Bash, else PowerShell; profile output that doesn't start with `{` makes JSON be read as plain text | Shim command is `node "<abs path>"` with no shell features; `init` verifies one round trip |
| Exec form (`command` + `args`) | Documented, version not stated; docs reference features from 2.1.29x, newer than installed 2.1.278 | Do not depend on exec form in v0; use the quoted shell form, which works on 2.1.278 (observed) |
| Headless detection | No stdin field or env var documented | Keep 05's rule: `CI`, `PROSEGATE_MODE`, else interactive |
| Workspace trust | Interactive sessions hold back all hooks until the trust dialog is accepted; `-p` treats the folder as trusted | `init` output tells the user hooks start after trust; not a Prosegate failure |
| `--bare` | Skips hooks, plugins and MCP servers | Documented limitation |
| User-scope MCP | `claude mcp add --scope user …` writes `~/.claude.json` | `init` uses the CLI command rather than editing `~/.claude.json` by hand |
| Plugin packaging | Plugins can bundle `hooks/hooks.json` and `.mcp.json`; installed via a marketplace | Logged as a post-v0 install route (DEBT); v0 writes settings per plan |
