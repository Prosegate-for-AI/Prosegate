To rotate the signing key, first **pause the deploy pipeline** so that no release picks up a half-changed config. Then generate the new key with `keygen --rotate` and store it in the **secrets manager** under a new version name. Update the **KEY_VERSION** variable in staging and run the **smoke tests** against it. They take ten minutes. If they pass and nothing else in the dashboards looks odd, promote the same change to production during a **low traffic window**. Keep the old key active for **24 hours** so that tokens already issued stay valid for their full lifetime. After that, revoke the old key and resume the pipeline. Record the rotation date in the runbook and set a reminder for the next one, which falls due **90 days** from today. Ask someone on the platform team to confirm the new key id appears in the public key endpoint before you close the ticket.
